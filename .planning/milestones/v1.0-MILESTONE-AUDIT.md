### Integration Gaps

1. **`PYDANTIC_AI_GATEWAY_API_KEY` not injected into Agent**
   - `settings.PYDANTIC_AI_GATEWAY_API_KEY` is defined in `config.py:42`
   - `servicer.py` does not import `settings` — the key has no path to the gateway call
   - At runtime, gateway auth must come from a raw `PYDANTIC_AI_GATEWAY_API_KEY` env var or it will fail

2. **`request.llm_model` bypassed in Agent construction**
   - servicer.py:95 calls `_to_gateway_model(LLM_DEFAULT_GATEWAY_MODEL)` — hard-coded constant
   - Should be `_to_gateway_model(request.llm_model)` to honor the caller's model choice
   - `LLM_GATEWAY_LIST` validation logic is dead code as a result

## E2E Flows

### ✓ Complete: Happy Path Voice Generation

1. `POST /public/api/brands/` → brand created, `id` returned
2. `POST /public/api/brands/{brand_id}/voices:generate` with `writing_samples` + `llm_model`
3. Brand existence check → VoiceProfile version computed → Agent called → result validated by Pydantic → DB row persisted → `VoiceProfileResponse` returned with `version == 1`

### ✓ Complete: 404 / 422 Guards

- Unknown `brand_id` → 404 ✓
- Missing `writing_samples` → 422 ✓

### ✓ By design: LLM model selection

- `request.llm_model` is a record/label field: stored in DB, echoed in response
- Actual inference model is internally configured server-side (`LLM_DEFAULT_GATEWAY_MODEL`)
- Rationale: model selection is an internal concern, not caller-controlled

### ✗ Untested: Version Increment

- Second `POST /brands/{brand_id}/voices:generate` → version increment logic is correct in code
